# Strenger Code-Review-Skill erzwingt Strukturvereinfachung

Viking beschreibt den Skill „Thermo-Nuclear Code Quality Review“, den er Cursor zuschreibt. Die Regeln stammen aus seiner eigenen Übersetzung, nicht aus dem Skill-Text. Belegt ist nur ein Selbstversuch mit einem Projekt und eine Anwenderstimme im Thread.

## Kernaussagen
- Vereinfachung kommt vor Detailkritik: Der Review sucht Refactorings, die Branches, Helper oder Modi ganz entfallen lassen. → [[Plan-first-mit-getrenntem-Review]]
- Harte Grenze: Kein PR darf eine Datei von unter 1000 auf über 1000 Zeilen bringen. Temporäre `if`-Zweige und Einmal-Flags gelten als Designfehler.
- Ein Antwortender nutzt ihn erst nach Abschluss eines ganzen Features, kleine Tasks bekommen einen leichten Review.

## Einordnung
Selbstberichtet, ohne Messung. Der Autor fand so viele Befunde, dass er sie nicht mehr abarbeitete: Die Strenge erzeugt Review-Schulden, taugt also eher für neue Projekte. Die 1000-Zeilen-Grenze ist eine Heuristik, keine Qualitätsmessung.
