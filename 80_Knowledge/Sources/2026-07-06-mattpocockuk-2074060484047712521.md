# Dev-Server-Log in Datei spiegeln, damit Agents Laufzeitfehler sehen

Matt Pocock empfiehlt einen Zwei-Schritt-Trick fürs Debugging: den Dev-Server per `tee` in eine lokale Datei schreiben lassen und in `AGENTS.md` auf diese Datei verweisen. Der Agent liest die Ausgabe, ohne den Prozess zu besitzen. Das ist ein Praxistipp ohne Messung, technisch aber gut nachvollziehbar.

## Kernaussagen

- Der Server läuft weiter unter Deiner Kontrolle; der Agent bekommt nur lesenden Zugriff über die Logdatei.
- Der Zeiger in `AGENTS.md` ist der Entdeckungsmechanismus → [[AGENTS-md-Onboarding-Design]]

## Einordnung

Kostet fast nichts, vermeidet Prozessverwaltung durch den Agent. Grenze: Die Logdatei wächst und kann viel Kontext fressen, wenn der Agent sie komplett liest; ein Hinweis auf `tail` oder Rotation wäre sinnvoll.
