# Unsloth: Laya Decision Models lokal ab 4 GB RAM mit Jev-kompatibler API

Unsloth kündigt am 28.09.2026 an, dass sich das Decision-Modell „Laya“ (laut Guide eine offene Jev-Alternative) lokal über Unsloth Desktop betreiben lässt, auf CPU, Mac, Windows, Linux und GPU. Die Angaben sind Herstellerangaben aus einem Tweet und einem Guide-Bild, ohne Messwerte zu Qualität oder Latenz.

![Guide-Ausschnitt mit Modelltabelle, Decision-API-Einstellungen und Fragetypen](../../00_Inbox/Quellen/X/medien/2026-09-28-unslothai-2104592692072304916/01-photo.jpg)

## Modelle (Stand 28.09.2026, laut Guide-Bild)

- Multilingual (Standard): mindestens 4 GB RAM, 678 MB, über 100 Sprachen, 1024 Token Kontext.
- English: 5 GB RAM, 846 MB, größerer Encoder, 512 Token Kontext.
- Typed decisions: 5 GB RAM, 846 MB, nur Englisch, für Rechnungen, Security-Incidents und Agent-Traces.

CPU ist Standard; auf GPU bleibt das Modell bis „Unload“ oder Neustart im Speicher, bei GPU-Speichermangel fällt Laya auf CPU zurück.

## Betrieb und Fragetypen

In den Settings unter API „Decision API“ mit „Serve requests“ aktivieren, das Modell wird dann geladen. Bestehende Jev-Integrationen sollen funktionieren, indem man sie auf den lokalen Server zeigt; Daten bleiben auf dem Gerät. Drei Fragetypen: Ja/Nein (Wahrscheinlichkeit für Ja, 0 bis 1), `choice` (wahrscheinlichste Option plus Wahrscheinlichkeit je Option) und `score` (Position auf einer Skala).

## Einordnung

Belegt ist nur das Angebot, nicht die Entscheidungsqualität. Ein Modell von unter 1 GB Größe mit 512 bis 1024 Token Kontext taugt nur für kurze Eingaben mit festem Antwortraum; lange Tickets oder Traces müssten gekürzt werden. Die Kalibrierungsfrage aus Chawlas Artikel bleibt offen. Im Bild steht als Typ `noul` für Ja/Nein, vermutlich ein Tippfehler für `bool`; das ist nicht geprüft.
