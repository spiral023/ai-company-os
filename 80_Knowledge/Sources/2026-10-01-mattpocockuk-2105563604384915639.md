# Abstraktionen mit dem Deletion Test beurteilen

Pocock schlägt vor, mit `/codebase-design` nach Shallow Modules zu suchen und den **Deletion Test** auf mögliche Entfernungskandidaten anzuwenden. Gemeint ist eine gedankliche Prüfung, keine Aufforderung zum sofortigen Löschen.

## Wo landet die Komplexität ohne das Modul?

Der lokale Checkout `mattpocock/skills@4588b32`, `skills/engineering/codebase-design/SKILL.md`, definiert Deep Modules über viel Verhalten hinter einer kleinen Schnittstelle. Beim Deletion Test wird gefragt: Verschwindet Komplexität mit dem Modul, war es möglicherweise eine bloße Durchreichung; verteilt sie sich stattdessen erneut auf viele Aufrufer, erfüllt die Abstraktion eine Aufgabe. Das ist eine am Repo bestätigte Erläuterung zum knappen Post.

Eine spätere Antwort verteidigt Abstraktionen grundsätzlich als tokeneffizient und wünschenswert. Die andere Antwort bezieht sich auf eine nicht vollständig archivierte Frage und liefert keine rekonstruierbare Methode.

## Einordnung

Der API-Abruf enthielt den Originalpost, die Thread-Suche zunächst nur zwei spätere Antworten; das lokale Archiv wurde aus dem vorhandenen Cache um den Originalpost ergänzt. Drei Autor-Posts sind damit erhalten, die Unterhaltung bleibt unvollständig. Eigeneinschätzung: Der Test bewertet die Verlagerung von Komplexität, nicht die Zahl der Dateien oder Codezeilen. Tokenersparnis ist hier eine Autorenbehauptung ohne Messung. Öffentliche Schnittstellen, Seiteneffekte und Abhängigkeiten müssen vor tatsächlichem Entfernen separat geprüft werden; es wurde kein Code gelöscht.
