# Ausführbaren Code auch bei Spec-Steuerung als Qualitätsgegenstand behalten

Matt Pocock setzt im Startpost Code ins Zentrum der Entwicklung. Im weiteren Austausch relativiert er die zugespitzte Gegenüberstellung: Spec-Driven Development kann weiterhin Wert auf den tatsächlichen Code legen.

## Kernaussagen

- Code ist ausführbar und bildet die Umgebung, in der spätere Agents arbeiten.
- Schlechter Code bleibt auch bei automatisierter Erstellung ein Qualitätsproblem.
- Der Thread verwirft Spezifikationen nicht pauschal; Pocock fragt abschließend nach dem Abgleich jeder Codeänderung mit der Spec → [[Plan-first-mit-getrenntem-Review]].

## Einordnung
