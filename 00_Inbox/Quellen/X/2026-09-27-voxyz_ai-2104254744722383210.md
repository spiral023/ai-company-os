Then I saw I was burning through my weekly limit too fast, so I switched build and QA to 𝗴𝗿𝗼𝘂𝗽𝘀 𝗼𝗳 𝟯. Not one of those 24 agents threw an error. That actually surprised me.

How the work was split (5 workflows, just over 7 hours of run time combined):
→ Mining (71): read posts, articles and drafts in batches, picked out the methods that could become skills, and sorted them into 14 categories
→ Planning (9): 4 designers each drafted a version, a chief architect wrote the blueprint, 3 critics flagged 50 problems, and the fixes went into the final plan
→ Scaffold (1): set up the repo skeleton and validation scripts before anyone else started
→ Build (21): 3 lanes in parallel, one agent at a time in each lane, one writing and one reviewing
→ QA (3): each checked one area and never edited another's files

Now I match every agent's effort to its job: low for mechanical work like mining, medium for writing, high for review, xhigh for the final decision.

That said, I'm still checking whether these skills actually work well. Running this on my own account is just one example. The same approach can be applied to any kind of work that builds up over time. Once I've confirmed the material is genuinely useful, I'll probably put the site up so everyone can browse it.
